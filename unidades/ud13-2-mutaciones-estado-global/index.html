    Mutaciones, Invalidación y Actualizaciones Optimistas

    1. Concepto de Mutaciones y el Hook useMutation

    A diferencia de las consultas de lectura (useQuery), las mutaciones representan operaciones de escritura, creación, actualización o borrado de datos en el servidor (métodos HTTP POST, PUT, PATCH, DELETE).

    TanStack Query proporciona el hook useMutation para gestionar el ciclo de vida asíncrono de estas operaciones, ofreciendo control sobre sus estados (isPending, isError, isSuccess) y permitiendo sincronizar la caché local tras la modificación remota.

    flowchart LR
    A["Acción del Usuario (Click / Form)"] --> B["mutate(datos)"]
    B --> C["useMutation Execution"]
    C -->|HTTP Request| D["Servidor / API REST"]
    D -->|Respuesta Exitosa| E["onSuccess Callback"]
    D -->|Error de Red/API| F["onError Callback"]
    E --> G["invalidateQueries / setQueryData"]
    G --> H["Re-render Automático de UI"]

    2. Anatomía de useMutation y sus Callbacks

    El hook useMutation recibe una función de mutación (mutationFn) y un objeto opcional de configuración con callbacks para reaccionar a los diferentes momentos del ciclo de vida:

    import { useMutation, useQueryClient } from '@tanstack/react-query';

interface NuevoUsuario {
  nombre: string;
  email: string;
}

async function crearUsuarioAPI(nuevoUsuario: NuevoUsuario) {
  const res = await fetch('[https://api.ejemplo.com/usuarios](https://api.ejemplo.com/usuarios)', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(nuevoUsuario),
  });
  if (!res.ok) throw new Error('No se pudo crear el usuario');
  return res.json();
}

export function FormularioCrearUsuario() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: crearUsuarioAPI,
    onSuccess: (data) => {
      console.log('Usuario creado con éxito:', data);
      // Invalida la caché para que la lista de usuarios se vuelva a solicitar
      queryClient.invalidateQueries({ queryKey: ['usuarios'] });
    },
    onError: (error: Error) => {
      console.error('Error durante la creación:', error.message);
    },
    onSettled: () => {
      // Se ejecuta SIEMPRE al finalizar (éxito o error)
      console.log('Operación de mutación finalizada');
    },
  });

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    mutation.mutate({ nombre: 'Ana Gómez', email: 'ana@example.com' });
  };

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit" disabled={mutation.isPending}>
        {mutation.isPending ? 'Guardando...' : 'Crear Usuario'}
      </button>

      {mutation.isError && (
        <p style={{ color: 'red' }}>Error: {mutation.error.message}</p>
      )}
      {mutation.isSuccess && (
        <p style={{ color: 'green' }}>¡Usuario creado correctamente!</p>
      )}
    </form>
  );
}

    3. Estrategias de Sincronización de Caché

    Tras ejecutar una mutación existen dos estrategias principales para mantener la interfaz actualizada:

    3.1. Invalidación de Consultas (invalidateQueries)

    Es el método preferido e idóneo para la mayoría de los casos. Marca una o varias claves de consulta como obsoletas (stale) e invalida inmediatamente las que estén activas en la pantalla, forzando un refetch automático contra el servidor.

    // Invalida exactamente todas las consultas que comiencen por 'usuarios'
queryClient.invalidateQueries({ queryKey: ['usuarios'] });

// Invalida solo la consulta específica con un ID
queryClient.invalidateQueries({ queryKey: ['usuarios', userId] });

    3.2. Actualización Directa de la Caché (setQueryData)

    Útil cuando la API de respuesta tras la mutación devuelve la entidad completa actualizada y se desea evitar una petición HTTP de lectura adicional.

    queryClient.setQueryData(['usuarios', userId], (usuarioViejo: Usuario | undefined) => {
  if (!usuarioViejo) return undefined;
  return { ...usuarioViejo, nombre: 'Nuevo Nombre' };
});

    4. Actualizaciones Optimistas (Optimistic Updates)

    Una actualización optimista actualiza la interfaz de usuario de forma inmediata asumiendo que la petición al servidor va a tener éxito. Si la petición falla posteriormente, la interfaz revierte de forma automática sus cambios al estado previo almacenado en la caché.

    Flujo de Trabajo en TanStack Query:

    1. onMutate: Se cancelan las peticiones pendientes de esa clave, se guarda una copia del estado anterior y se actualiza la caché optimistamente.
    2. onError: Se restaura la caché con el estado guardado previo.
    3. onSettled: Se invalida la consulta para sincronizar definitivamente el estado real del servidor.
    sequenceDiagram
    autonumber
    actor User as Usuario
    participant UI as Interfaz React
    participant Cache as Caché TanStack Query
    participant Server as Servidor / API

    User->>UI: Modifica/Elimina elemento
    UI->>Cache: 1. onMutate(): Guarda copia previa & inserta datos optimistas
    Cache->>UI: 2. Renderiza cambios al instante (0ms percibidos)
    UI->>Server: 3. Envía petición de mutación HTTP

    alt Petición Exitosa
        Server-->>UI: Responde 200 OK
        UI->>Cache: 4. onSettled(): Invalida consulta y sincroniza con el servidor
    else Petición Fallida (Error)
        Server-->>UI: Responde Error 500 / Timeout
        UI->>Cache: 4. onError(): Rollback al estado anterior guardado
        Cache->>UI: 5. Restaura la interfaz previa y notifica el error
    end

    5. Inspección y Depuración (ReactQueryDevtools)

    Para depurar de forma visual el estado de las claves de consulta, tiempos de caducidad, datos en caché y ejecuciones de mutaciones, TanStack Query ofrece las DevTools oficiales.

    import { ReactQueryDevtools } from '@tanstack/react-query-devtools';

export function App() {
  return (
    <QueryClientProvider client="{queryClient}">
      <MiAplicacion/>
      {/* Devtools integradas solo en modo de desarrollo */}
      <ReactQueryDevtools buttonPosition="bottom-right" initialIsOpen="{false}"/>
    </QueryClientProvider>
  );
}

    6. Demostración Práctica Completa: Lista de Tareas CRUD con Actualizaciones Optimistas

    Esta aplicación implementa la gestión completa de tareas (obtención, creación y eliminación) combinando useQuery, useMutation, invalidación de caché y actualización optimista:

    import React, { useState } from 'react';
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';

// --- TYPES ---
interface Tarea {
  id: number;
  texto: string;
}

// SIMULACIÓN DE API REST CON RETRASO
let baseDeDatosTareas: Tarea[] = [
  { id: 1, texto: 'Estudiar useEffect y BOM' },
  { id: 2, texto: 'Configurar React Router v6/v7' },
];

const apiTareas = {
  getTareas: async (): Promise<Tarea[]> => {
    await new Promise((resolve) => setTimeout(resolve, 600));
    return [...baseDeDatosTareas];
  },

  crearTarea: async (texto: string): Promise<Tarea> => {
    await new Promise((resolve) => setTimeout(resolve, 800)); // Simula latencia
    if (Math.random() < 0.2) {
      throw new Error('Fallo aleatorio de servidor al crear la tarea');
    }
    const nuevaTarea = { id: Date.now(), texto };
    baseDeDatosTareas.push(nuevaTarea);
    return nuevaTarea;
  },

  eliminarTarea: async (id: number): Promise<number> => {
    await new Promise((resolve) => setTimeout(resolve, 500));
    baseDeDatosTareas = baseDeDatosTareas.filter((t) => t.id !== id);
    return id;
  },
};

// --- COMPONENTE PRINCIPAL ---
export function GestorTareasOptimista() {
  const [textoNueva, setTextoNueva] = useState('');
  const queryClient = useQueryClient();

  // 1. QUERY: Lectura de tareas
  const { data: tareas = [], isLoading, isError, error } = useQuery({
    queryKey: ['tareas'],
    queryFn: apiTareas.getTareas,
  });

  // 2. MUTACIÓN OPTIMISTA: Crear Tarea
  const mutacionCrear = useMutation({
    mutationFn: apiTareas.crearTarea,

    // Se ejecuta ANTES de enviar la petición HTTP
    onMutate: async (textoNuevaTarea) => {
      // Cancelar peticiones de 'tareas' en curso para que no sobreescriban la actualización optimista
      await queryClient.cancelQueries({ queryKey: ['tareas'] });

      // Guardar copia de seguridad del estado anterior de la caché
      const tareasPrevias = queryClient.getQueryData<Tarea[]>(['tareas']);

      // Crear objeto provisional optimista
      const tareaProvisional: Tarea = { id: Date.now(), texto: `${textoNuevaTarea} (Guardando...)` };

      // Actualizar la caché local optimistamente
      queryClient.setQueryData<Tarea[]>(['tareas'], (viejas = []) => [...viejas, tareaProvisional]);

      // Devolver el contexto con las tareas previas para poder restaurar en caso de fallo
      return { tareasPrevias };
    },

    // Si la mutación falla, ejecutamos ROLLBACK
    onError: (_err, _variables, context) => {
      if (context?.tareasPrevias) {
        queryClient.setQueryData(['tareas'], context.tareasPrevias);
      }
      alert('❌ Error al guardar la tarea. Se han revertido los cambios.');
    },

    // Siempre invalida y sincroniza con el servidor al terminar
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['tareas'] });
    },
  });

  // 3. MUTACIÓN: Eliminar Tarea
  const mutacionEliminar = useMutation({
    mutationFn: apiTareas.eliminarTarea,
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['tareas'] });
    },
  });

  const handleCrear = (e: React.FormEvent) => {
    e.preventDefault();
    if (!textoNueva.trim()) return;
    mutacionCrear.mutate(textoNueva);
    setTextoNueva('');
  };

  return (
    <div style={{ maxWidth: '500px', margin: '20px auto', fontFamily: 'sans-serif' }}>
      <h2>Gestor de Tareas (Optimistic UI)</h2>

      <form onSubmit={handleCrear} style={{ display: 'flex', gap: '8px', marginBottom: '15px' }}>
        <input
          type="text"
          value={textoNueva}
          onChange={(e) => setTextoNueva(e.target.value)}
          placeholder="Escriba una nueva tarea..."
          style={{ flex: 1, padding: '8px' }}
        />
        <button type="submit" disabled={mutacionCrear.isPending}>
          Añadir
        </button>
      </form>

      {isLoading && <p>⌛ Cargando tareas...</p>}
      {isError && <p style={{ color: 'red' }}>Error: {(error as Error).message}</p>}

      <ul style={{ listStyle: 'none', padding: 0 }}>
        {tareas.map((tarea) => (
          <li
            key={tarea.id}
            style={{
              display: 'flex',
              justifyContent: 'space-between',
              alignItems: 'center',
              padding: '10px',
              borderBottom: '1px solid #ddd',
              backgroundColor: tarea.texto.includes('(Guardando...)') ? '#fffde7' : 'transparent',
            }}
          >
            <span>{tarea.texto}</span>
            <button
              onClick={() => mutacionEliminar.mutate(tarea.id)}
              style={{ background: '#ff5252', color: 'white', border: 'none', padding: '4px 8px', borderRadius: '4px', cursor: 'pointer' }}
            >
              Eliminar
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}
