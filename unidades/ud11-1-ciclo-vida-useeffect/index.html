    12.1: Ciclo de Vida y Efectos Secundarios (useEffect)

    1. Naturaleza de los Efectos Secundarios y Modelo Mental de Sincronización

    En la arquitectura declarativa de React, las funciones de componente deben comportarse como funciones puras durante la fase de renderizado: dado un mismo conjunto de props y state, deben devolver exactamente el mismo marcado JSX sin alterar ningún estado fuera de su alcance (scope).

    Un efecto secundario (side effect) es cualquier operación que afecte al entorno externo fuera del alcance local del componente o que no forme parte del cálculo directo del JSX:

    • Peticiones HTTP de red (APIs REST, GraphQL).
    • Suscripciones a eventos nativos del navegador (window.resize, window.scroll, online/offline).
    • Manipulación imperativa directa del DOM nativo (no gestionada por Virtual DOM).
    • Temporizadores (setInterval, setTimeout).
    • Lectura/escritura en almacenamiento local (localStorage, sessionStorage).

    1.1. Matriz de Dependencias: undefined vs [] vs [dep1, dep2]

    El hook useEffect recibe dos parámetros: la función del efecto y la matriz o array de dependencias (dependencies array). El comportamiento del efecto depende estrictamente de cómo se configure esta matriz:

    \[\text{Frecuencia de Ejecución} = f(\text{Matriz de Dependencias})\]
    import { useEffect } from 'react';

// Caso A: Sin matriz de dependencias (undefined)
useEffect(() => {
  // Se ejecuta tras el montaje inicial Y tras CADA re-renderizado del componente
});

// Caso B: Matriz de dependencias vacía ([])
useEffect(() => {
  // Se ejecuta ÚNICAMENTE una vez tras el montaje inicial
}, []);

// Caso C: Matriz con valores específicos ([dep1, dep2])
useEffect(() => {
  // Se ejecuta al montar Y cada vez que 'dep1' o 'dep2' cambien de valor
}, [dep1, dep2]);

    Mecanismo Interno de Comparación de Dependencias

    En cada re-renderizado, React compara cada elemento del array de dependencias actual con su valor en el renderizado anterior utilizando el algoritmo Object.is (comparación superficial):

    flowchart LR
    PrevDeps["Deps Render Previo: [a, b]"] --> DiffEngine{"Object.is(prev, next)"}
    NextDeps["Deps Render Actual: [a', b']"] --> DiffEngine

    DiffEngine -->|Al menos un valor cambió (false)| RunEffect["Ejecuta Efecto Secundario"]
    DiffEngine -->|Todos los valores idénticos (true)| SkipEffect["Omite Ejecución del Efecto"]

    Regla de Oro de Linting (react-hooks/exhaustive-deps): Cualquier variable local, prop o función declarada dentro del cuerpo del componente que se utilice dentro del useEffect DEBE incluirse obligatoriamente en el array de dependencias. Omitirla genera stale closures (cierres con datos obsoletos).

    2. Anatomía de la Función de Limpieza (Cleanup Function)

    Cuando un efecto crea una suscripción, inicia un temporizador o abre una conexión, estos recursos persisten en la memoria del navegador. Si el componente se re-renderiza o se desmonta sin liberar esos recursos, se produce una fuga de memoria (memory leak).

    Para evitar esto, la función pasada a useEffect puede retornar una función de limpieza (cleanup function).

    React->>Comp: Elimina componente del DOM
    Comp->>Effect: 🧹 EJECUTA CLEANUP de Render 2 (Limpia id=2)

    2.1. Momento Exacto de Ejecución de la Limpieza

    La función de limpieza devuelta por useEffect se ejecuta en dos situaciones:

    1. Antes de volver a ejecutar el efecto cuando una dependencia ha cambiado (limpia el efecto anterior antes de aplicar el nuevo).
    2. Cuando el componente se desmonta de la interfaz (se elimina del DOM Real).

    2.2. Cancelación de Peticiones Asíncronas con AbortController

    Un problema clásico en aplicaciones web es la condición de carrera (race condition): si un usuario cambia rápidamente de pestaña o de filtro, se envían múltiples peticiones HTTP. Si la primera petición (obsoleta) responde después de la última petición (válida), la interfaz mostrará datos incorrectos.

    La solución estándar en JavaScript moderno es la API AbortController:

    import React, { useState, useEffect } from 'react';

interface Usuario {
  id: number;
  nombre: string;
  email: string;
}

export function PerfilUsuarioCancellable({ usuarioId }: { usuarioId: number }) {
  const [usuario, setUsuario] = useState<Usuario null |>(null);
  const [cargando, setCargando] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    // 1. Instanciar el AbortController para esta ejecución del efecto
    const controller = new AbortController();
    const { signal } = controller;

    async function cargarDatos() {
      setCargando(true);
      setError(null);

      try {
        const respuesta = await fetch(
          `[https://jsonplaceholder.typicode.com/users/$](https://jsonplaceholder.typicode.com/users/$){usuarioId}`,
          { signal } // Vinculamos la señal de aborto a la petición fetch
        );

        if (!respuesta.ok) {
          throw new Error(`Error en la petición: ${respuesta.status}`);
        }

        const datos: Usuario = await respuesta.json();
        setUsuario(datos);
      } catch (err: unknown) {
        // Ignoramos el error si fue causado por la cancelación explícita
        if (err instanceof Error && err.name === 'AbortError') {
          console.log(`[ABORT] Petición cancelada para usuarioId: ${usuarioId}`);
        } else {
          setError((err as Error).message);
        }
      } finally {
        setCargando(false);
      }
    }

    cargarDatos();

    // 2. FUNCIÓN DE LIMPIEZA: Se ejecuta si usuarioId cambia o el componente se desmonta
    return () => {
      controller.abort(); // Cancela la petición HTTP en tránsito a nivel de red
    };
  }, [usuarioId]); // Se re-ejecuta cada vez que cambia usuarioId

  if (cargando) return <p>Cargando perfil...</p>;
  if (error) return <p style={{ color: 'red' }}>Error: {error}</p>;
  if (!usuario) return null;

  return (
    <div>
      <h3>{usuario.nombre}</h3>
      <p>Email: {usuario.email}</p>
    </div>
  );
}

    3. Integración con el Browser Object Model (BOM) y Web Storage

    3.1. Gestión de Eventos Globales de la Ventana (window)

    Para escuchar eventos del navegador como resize, keydown, scroll o cambios en el estado de la conexión (online/offline), se deben registrar los escuchadores dentro de un useEffect y eliminarlos en la función de limpieza:

    import React, { useState, useEffect } from 'react';

export function MonitorEstadoRed() {
  const [estaOnline, setEstaOnline] = useState<boolean>(navigator.onLine);

  useEffect(() => {
    const handleOnline = () => setEstaOnline(true);
    const handleOffline = () => setEstaOnline(false);

    // Suscripción a eventos del BOM
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);

    // Limpieza obligatoria para evitar fugas de memoria
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []); // Solo al montar y desmontar

  return (
    <div style={{
      padding: '10px',
      backgroundColor: estaOnline ? '#d4edda' : '#f8d7da',
      color: estaOnline ? '#155724' : '#721c24',
      borderRadius: '4px'
    }}>
      Estado de la Conexión: <strong>{estaOnline ? 'ONLINE' : 'OFFLINE'}</strong>
    </div>
  );
}

    3.2. Sincronización Declarativa con localStorage

    localStorage es una API síncrona imperativa del BOM. Para integrarla correctamente con React, la lectura inicial debe realizarse mediante lazy initial state en useState para evitar lecturas de disco innecesarias en cada render, y la persistencia debe sincronizarse mediante useEffect:

    import React, { useState, useEffect } from 'react';

export function ConfigUsuario() {
  // Inicialización perezosa (Lazy Initial State): Solo lee de localStorage en el PRIMER RENDER
  const [tema, setTema] = useState<'claro' | 'oscuro'>(() => {
    const temaGuardado = localStorage.getItem('app_tema');
    return (temaGuardado as 'claro' | 'oscuro') || 'claro';
  });

  // Efecto de sincronización con la API externa del BOM
  useEffect(() => {
    localStorage.setItem('app_tema', tema);
    document.body.className = `theme-${tema}`;
  }, [tema]); // Se ejecuta cada vez que cambia 'tema'

  return (
    <div>
      <p>Tema actual: <strong>{tema}</strong></p>
      <button onClick={() => setTema(tema === 'claro' ? 'oscuro' : 'claro')}>
        Alternar Tema
      </button>
    </div>
  );
}

    4. Encapsulación en Hooks Personalizados (Custom Hooks)

    Un Custom Hook es una función de JavaScript cuyo nombre comienza por use y que puede invocar otros Hooks de React (useState, useEffect, useRef, etc.). Permiten extraer y reutilizar la lógica con efectos secundarios manteniendo los componentes visuales limpios.

    4.1. Custom Hook 1: useWindowSize

    import { useState, useEffect } from 'react';

interface WindowSize {
  ancho: number;
  alto: number;
}

export function useWindowSize(): WindowSize {
  const [dimensiones, setDimensiones] = useState<WindowSize>({
    ancho: window.innerWidth,
    alto: window.innerHeight,
  });

  useEffect(() => {
    function handleResize() {
      setDimensiones({
        ancho: window.innerWidth,
        alto: window.innerHeight,
      });
    }

    window.addEventListener('resize', handleResize);

    return () => {
      window.removeEventListener('resize', handleResize);
    };
  }, []);

  return dimensiones;
}

    4.2. Custom Hook 2: useLocalStorage

    import { useState, useEffect } from 'react';

export function useLocalStorage<T>(clave: string, valorInicial: T): [T, (nuevoValor: T | ((val: T) => T)) => void] {
  // Lectura perezosa inicial
  const [valor, setValor] = useState<T>(() => {
    try {
      const item = localStorage.getItem(clave);
      return item ? JSON.parse(item) : valorInicial;
    } catch (error) {
      console.error(`Error leyendo clave de localStorage "${clave}":`, error);
      return valorInicial;
    }
  });

  // Sincronización
  useEffect(() => {
    try {
      localStorage.setItem(clave, JSON.stringify(valor));
    } catch (error) {
      console.error(`Error guardando en localStorage "${clave}":`, error);
    }
  }, [clave, valor]);

  return [valor, setValor];
}

    4.3. Custom Hook 3: useFetch con Soporte para Cancelación

    import { useState, useEffect } from 'react';

interface StateFetch<T> {
  datos: T | null;
  cargando: boolean;
  error: string | null;
}

export function useFetch<T>(url: string): StateFetch<T> {
  const [estado, setEstado] = useState<StateFetch<T>>({
    datos: null,
    cargando: true,
    error: null,
  });

  useEffect(() => {
    const controller = new AbortController();

    setEstado({ datos: null, cargando: true, error: null });

    fetch(url, { signal: controller.signal })
      .then((res) => {
        if (!res.ok) throw new Error(`HTTP Error Status: ${res.status}`);
        return res.json();
      })
      .then((data: T) => {
        setEstado({ datos: data, cargando: false, error: null });
      })
      .catch((err: unknown) => {
        if (err instanceof Error && err.name === 'AbortError') return;
        setEstado({ datos: null, cargando: false, error: (err as Error).message });
      });

    return () => controller.abort();
  }, [url]);

  return estado;
}

    5. Anti-patrones, Errores Comunes y React 18/19 Strict Mode

    5.1. Anti-patrón 1: Usar useEffect para Transformar Datos del Render

    ❌ INCORRECTO: Usar useEffect para calcular un estado derivado basándose en otro estado. Esto provoca un re-renderizado extra e innecesario.

    // ❌ INCORRECTO (Causa 2 renderizados consecutivos):
function ListaNombres({ personas }: { personas: { nombre: string }[] }) {
  const [total, setTotal] = useState(0);

  useEffect(() => {
    setTotal(personas.length); // 🔴 ERROR: Re-render innecesario
  }, [personas]);

  return <p>Total: {total}</p>;
}

    ✅ CORRECTO: Calcular el valor derivado directamente durante la fase de render (o con useMemo si es muy costoso):

    // ✅ CORRECTO (0 renderizados extra):
function ListaNombres({ personas }: { personas: { nombre: string }[] }) {
  const total = personas.length; // Calcule directamente en render
  return <p>Total: {total}</p>;
}

    5.2. Anti-patrón 2: Bucle Infinito de Renderizado

    Ocurre cuando un useEffect actualiza un estado que a su vez está incluido en su propio array de dependencias o cuando se pasa un objeto/array sin memorizar:

    // ❌ BUCLE INFINITO DE RENDERS:
function BucleInfinito() {
  const [contador, setContador] = useState(0);

  useEffect(() => {
    setContador(contador + 1); // Mutación de estado
  }, [contador]); // Depende del estado que acaba de mutar -> BUCLE INFINITO

  return <div>{contador}</div>;
}

    5.3. React Strict Mode y la Doble Ejecución de Efectos (Double Invocation)

    En entorno de desarrollo (development), cuando la aplicación está envuelta en <React.StrictMode>, React monta, desmonta y vuelve a montar intencionadamente cada componente:

    [Strict Mode en Desarrollo Execution Order]
1. Monta Componente
2. Ejecuta useEffect()
3. 🧪 SIMULA DESMONTAJE: Ejecuta Cleanup Function () => {}
4. Vuelve a Montar Componente
5. Vuelve a ejecutar useEffect()

    ¿Por qué sucede esto? Para forzar al desarrollador a detectar efectos que no implementaron la función de limpieza (cleanup function) adecuada. Si tu código se rompe cuando el efecto se ejecuta dos veces en desarrollo, tu efecto carece de función de limpieza o esta está mal diseñada.

    6. Cuadro Comparativo: Ciclo de Vida en Clases vs useEffect

    Fase del Ciclo de Vida Componentes de Clase (Legacy) Equivalente en Hooks (useEffect)
    Montaje Inicial componentDidMount() useEffect(() => { ... }, [])
    Actualización por Props/Estado componentDidUpdate(prevProps, prevState) useEffect(() => { ... }, [dep1, dep2])
    Desmontaje componentWillUnmount() useEffect(() => { return () => { /* Cleanup */ } }, [])
    Renderizado (Todas las Fases) render() Cuerpo principal de la función componente

    7. Demostración Práctica Completa: Buscador con Debounce, AbortController y Persistencia BOM

    Esta aplicación completa integra los conceptos trabajados en la Subunidad 12.1:

    • Implementación de un buscador interactivo contra la API de GitHub.
    • Debounce de 500ms utilizando setTimeout y su correspondiente función de limpieza para evitar spam de peticiones por cada pulsación de tecla.
    • **Cancelación de peticiones en tránsito con AbortController**.
    • Persistencia del historial de búsquedas en localStorage usando el custom hook useLocalStorage.
    • Detección de estado de red mediante un hook personalizado.
    import React, { useState, useEffect } from 'react';

// --- 1. TYPES & INTERFACES ---
interface Repository {
  id: number;
  name: string;
  html_url: string;
  stargazers_count: number;
  description: string;
}

interface GitHubSearchResponse {
  items: Repository[];
}

// --- 2. CUSTOM HOOKS ---

// Custom Hook para persistencia en localStorage
function useLocalStorage<T>(key: string, initialValue: T): [T, React.Dispatch<React.SetStateAction<T>>] {
  const [storedValue, setStoredValue] = useState<T>(() => {
    try {
      const item = window.localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch (error) {
      console.error(`Error reading key "${key}" from localStorage`, error);
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      window.localStorage.setItem(key, JSON.stringify(storedValue));
    } catch (error) {
      console.error(`Error setting key "${key}" to localStorage`, error);
    }
  }, [key, storedValue]);

  return [storedValue, setStoredValue];
}

// Custom Hook para escuchar estado online/offline del BOM
function useNetworkStatus(): boolean {
  const [isOnline, setIsOnline] = useState<boolean>(navigator.onLine);

  useEffect(() => {
    const handleOnline = () => setIsOnline(true);
    const handleOffline = () => setIsOnline(false);

    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);

    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);

  return isOnline;
}

// --- 3. COMPONENTE PRINCIPAL ---
export function BuscadorRepositoriosGitHub() {
  const [query, setQuery] = useState<string>('');
  const [debouncedQuery, setDebouncedQuery] = useState<string>('');
  const [repos, setRepos] = useState<Repository[]>([]);
  const [loading, setLoading] = useState<boolean>(false);
  const [error, setError] = useState<string | null>(null);

  // Historial en localStorage mediante Custom Hook
  const [historial, setHistorial] = useLocalStorage<string[]>('github_search_history', []);
  const isOnline = useNetworkStatus();

  // EFECTO 1: Debounce para retrasar la actualización de 'debouncedQuery' 500ms
  useEffect(() => {
    const timerId = setTimeout(() => {
      setDebouncedQuery(query);
    }, 500);

    // CLEANUP 1: Limpia el temporizador anterior si el usuario vuelve a escribir antes de 500ms
    return () => {
      clearTimeout(timerId);
    };
  }, [query]);

  // EFECTO 2: Fetch asíncrono con AbortController dependiente de 'debouncedQuery'
  useEffect(() => {
    // Si la búsqueda filtrada está vacía, reseteamos resultados
    if (!debouncedQuery.trim()) {
      setRepos([]);
      setLoading(false);
      setError(null);
      return;
    }

    const controller = new AbortController();
    const { signal } = controller;

    async function fetchRepos() {
      setLoading(true);
      setError(null);

      try {
        const response = await fetch(
          `[https://api.github.com/search/repositories?q=$](https://api.github.com/search/repositories?q=$){encodeURIComponent(debouncedQuery)}&per_page=5`,
          { signal }
        );

        if (!response.ok) {
          throw new Error(`Error HTTP: ${response.status}`);
        }

        const data: GitHubSearchResponse = await response.json();
        setRepos(data.items || []);

        // Guardar en el historial de localStorage sin duplicados
        setHistorial((prev) => Array.from(new Set([debouncedQuery, ...prev])).slice(0, 5));
      } catch (err: unknown) {
        if (err instanceof Error && err.name === 'AbortError') {
          console.log(`[ABORT] Petición cancelada para término: "${debouncedQuery}"`);
        } else {
          setError((err as Error).message);
        }
      } finally {
        setLoading(false);
      }
    }

    fetchRepos();

    // CLEANUP 2: Cancela la petición HTTP si el usuario cambia el texto o se desmonta
    return () => {
      controller.abort();
    };
  }, [debouncedQuery, setHistorial]);

  return (
    <div style={{ maxWidth: '650px', margin: '20px auto', fontFamily: 'sans-serif' }}>
      <h2>Buscador de Repositorios (GitHub API)</h2>

      {/* Indicador de Red del BOM */}
      <div style={{
        padding: '8px',
        marginBottom: '15px',
        borderRadius: '4px',
        backgroundColor: isOnline ? '#e8f5e9' : '#ffebee',
        color: isOnline ? '#2e7d32' : '#c62828'
      }}>
        Red: <strong>{isOnline ? '🟢 Conectado' : '🔴 Sin Conexión'}</strong>
      </div>

      {/* Input de Búsqueda */}
      <input
        type="text"
        placeholder="Escriba para buscar (ej. react, typescript)..."
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        style={{ width: '100%', padding: '10px', fontSize: '16px', boxSizing: 'border-box' }}
      />

      {/* Historial almacenado en LocalStorage */}
      {historial.length > 0 && (
        <div style={{ marginTop: '10px' }}>
          <small>Búsquedas recientes: </small>
          {historial.map((item, idx) => (
            <button
              key={idx}
              onClick={() => setQuery(item)}
              style={{ marginRight: '5px', padding: '2px 8px', fontSize: '12px', cursor: 'pointer' }}
            >
              {item}
            </button>
          ))}
        </div>
      )}

      {/* Estado de Carga */}
      {loading && <p style={{ color: '#0288d1' }}>🔎 Buscando repositorios (Debounced & Cancelable)...</p>}
      {error && <p style={{ color: '#d32f2f' }}>❌ Error: {error}</p>}

      {/* Resultados de la Búsqueda */}
