    UD 8: Eventos y Estado con useState (RA5) — Visión General y Mapa Curricular

    1. Presentación y Contextualización Curricular

    La Unidad Didáctica 8 representa el punto de inflexión donde las interfaces estáticas y compuestas desarrolladas en la UD 7 se transforman en aplicaciones web dinámicas, reactivas e interactivas.

    En las unidades anteriores se estableció la sintaxis JSX, el tipado con TypeScript y la arquitectura de componentes basada en propiedades (props) e inmutabilidad. Sin embargo, una interfaz de usuario cliente real debe responder en tiempo real a las acciones del usuario (clics, pulsaciones de teclas, desplazamientos, envío de formularios) y mantener una memoria interna de su situación actual.

    En esta unidad se aborda cómo React revoluciona el manejo de la interacción cliente mediante dos pilares fundamentales:

    1. Eventos Sintéticos (SyntheticEvent): Una capa de abstracción sobre el sistema de eventos nativo del navegador que garantiza un comportamiento homogéneo multiplataforma y una delegación de eventos altamente eficiente.
    2. Estado Local (useState) y Custom Hooks: El mecanismo declarativo para almacenar y mutar la memoria de un componente, desencadenando ciclos de renderizado (Re-renders) automáticos y permitiendo encapsular la lógica de negocio reactiva en funciones reutilizables.

    2. Resultado de Aprendizaje y Criterios de Evaluación (RA5)

    Esta unidad didáctica desarrolla de forma directa los contenidos y competencias asignados al Resultado de Aprendizaje 5 (RA5) del currículo oficial de Desarrollo Web en Entorno Cliente (DWEC):

    RA5: Desarrolla aplicaciones web dinámicas integrando la gestión de eventos de usuario, la persistencia y actualización del estado local, y la reutilización de lógica mediante componentes y hooks personalizados.

    Desglose Detallado de Criterios de Evaluación (CE):

    • CE5.a: Se han identificado las diferencias entre el sistema de eventos nativo del DOM del navegador y la envolvente sintética (SyntheticEvent) de React.
    • CE5.b: Se han asociado manejadores de eventos (event handlers) a elementos JSX para capturar interacciones de usuario (clic, cambios en formularios, pulsaciones de teclado, ratón) pasando argumentos de forma segura.
    • CE5.c: Se ha declarado e inicializado el estado local de componentes funcionales mediante el hook useState, aplicando tipos estrictos con TypeScript.
    • CE5.d: Se ha garantizado la inmutabilidad del estado en operaciones de actualización de primitivos, objetos y arrays, evitando la mutación directa.
    • CE5.e: Se han ejecutado actualizaciones de estado asíncronas y acumulativas utilizando funciones actualizadoras (functional state updates).
    • CE5.f: Se ha aplicado el patrón de elevación del estado (Lifting State Up) para compartir información entre componentes hermanos a través de callbacks pasados por props.
    • CE5.g: Se ha abstraído la lógica reactiva y la gestión de eventos en Hooks Personalizados (Custom Hooks) reutilizables que respetan estrictamente las Reglas de los Hooks.

    4. Mapa Conceptual y Arquitectura del Flujo de Interacción

    El siguiente diagrama detalla la arquitectura completa de un ciclo de interacción en React, desde que el usuario realiza una acción física hasta que la pantalla refleja el nuevo estado:

    sequenceDiagram
    autonumber
    actor Usuario as Usuario (Navegador)
    participant DOM as DOM Nativo
    participant Root as Contenedor Raíz (React Root)
    participant Handler as Manejador de Eventos (JSX)
    participant State as Estado (useState)
    participant Reconciliation as Motor de Reconciliación (Virtual DOM)

    Usuario->>DOM: Realiza una acción (ej. Clic en un <button>)
    DOM->>Root: El evento se propaga hasta el contenedor raíz (Delegación)
    Root->>Handler: React envuelve el evento nativo en un SyntheticEvent y llama al Handler
    Handler->>State: Invoca a la función actualizadora (ej. setCount(nuevoValor))
    Note over State: React encola la actualización del estado<br>(Automatic Batching)
    State->>Reconciliation: Desencadena un re-renderizado del componente: UI = f(NuevoEstado)
    Reconciliation->>DOM: Calcula diferencias (Diffing) y aplica parches mínimos en el DOM Real
    DOM-->>Usuario: La interfaz muestra los datos actualizados dinámicamente

    5. Justificación Pedagógica y Cambio de Paradigma

    5.1. De la Manipulación Imperativa del DOM a la Declaratividad Reactiva

    En el desarrollo tradicional con JavaScript Vanilla, la actualización de la interfaz requería un procedimiento imperativo de tres pasos:

    1. Buscar el nodo en el DOM (document.querySelector).
    2. Escuchar el evento mediante addEventListener.
    3. Modificar manualmente el nodo (element.textContent = nuevoValor o element.classList.add()).

    Este enfoque imperativo se vuelve frágil a medida que la aplicación crece, ya que el estado real de la aplicación queda disperso en el propio DOM, generando incoherencias visuales.

    En React, el DOM es una consecuencia, no una fuente de verdad. La interfaz de usuario es una función pura del estado:

    $$\text{UI} = f(\text{Estado})$$

    Cuando el estado cambia mediante useState, React vuelve a ejecutar la función del componente, calcula las diferencias en el DOM Virtual y actualiza la pantalla automáticamente.

    5.2. Los Cinco Pilares de la Interactividad en la UD 8

    1. Abstracción SyntheticEvent y Delegación Cero-Coste

    React no adjunta escuchadores de eventos (addEventListener) a cada elemento individual del DOM. En su lugar, utiliza un único escuchador global en el contenedor raíz de la aplicación (Event Delegation). Cuando ocurre una interacción, React envuelve el evento nativo del navegador en un objeto SyntheticEvent, garantizando que propiedades como e.target o e.preventDefault() funcionen exactamente igual en cualquier navegador o dispositivo.

    2. Inmutabilidad como Motor del Re-renderizado

    En JavaScript, los objetos y arrays se comparan por referencia en memoria, no por valor. Para que React detecte que el estado ha cambiado y deba volver a renderizar la interfaz, el estado nunca se debe mutar directamente (ej. lista.push(item) o usuario.nombre = 'Ana'). En su lugar, se deben crear copias totalmente nuevas con las modificaciones aplicadas (ej. setLista([...lista, nuevoItem])).

    // ❌ INCORRECTO: Mutación directa (React NO detecta el cambio ni re-renderiza)
const agregarIncorrecto = () => {
  items.push('Nuevo Elemento');
  setItems(items); // La referencia en memoria es la misma
};

// ✅ CORRECTO: Inmutabilidad mediante operador Spread
const agregarCorrecto = () => {
  setItems([...items, 'Nuevo Elemento']); // Nueva referencia en memoria
};

    3. Actualizaciones Funcionales y Batching Asíncrono

    React agrupa múltiples llamadas de actualización de estado que ocurren dentro del mismo evento para ejecutarlas en un único ciclo de renderizado (Automatic Batching). Por ello, si una actualización depende del valor inmediatamente anterior del estado, debe utilizarse la forma funcional:

    // Si llamamos a esto 3 veces seguidas en el mismo evento, solo sumará 1 debido al batching:
// setCount(count + 1);

// Forma funcional correcta: garantiza la lectura del estado acumulado
setCount((prevCount) => prevCount + 1);

    4. Elevación del Estado (Lifting State Up)

    Cuando dos o más componentes hermanos necesitan compartir información o reaccionar a la misma interacción, el estado no debe duplicarse. El patrón correcto consiste en elevar el estado al ancestro común más cercano y pasar el valor hacia los hijos mediante props, acompañado de una función callback para permitir que los hijos soliciten cambios.

    5. Custom Hooks: Reutilización de Lógica Reactiva

    Los Hooks Personalizados son funciones de JavaScript cuyo nombre comienza por use y que pueden llamar a otros hooks de React (useState, useEffect, etc.). Permiten extraer la lógica de estado y los manejadores de eventos fuera de los componentes visuales, promoviendo el principio de responsabilidad única (SoC) y la reutilización de código limpia.

    6. Cuadro Comparativo de Paradigmas: Interacción y Estado

    El siguiente cuadro sintetiza los cambios conceptuales entre el desarrollo imperativo en JavaScript Vanilla y la arquitectura declarativa de React que se dominará en esta unidad:

    Dimensión JS Vanilla (Imperativo / DOM Directo) React (Declarativo / SyntheticEvents & useState)
    Escuchadores de Eventos element.addEventListener('click', fn) en cada nodo Atributos camelCase en JSX (onClick={fn}) con delegación raíz
    Objeto de Evento Evento nativo del navegador (MouseEvent, KeyboardEvent) Instancia normalizada de SyntheticEvent
    Fuente de Verdad de Datos El propio DOM (input.value) o variables globales Estado local reactivo (useState)
    Actualización de la UI Manual: element.innerHTML / element.textContent Automática: React re-renderiza al detectar un nuevo estado
    Modificación de Datos Mutación directa de variables/objetos Inmutabilidad estricta: Creación de nuevas referencias
    Comunicación entre Módulos Eventos personalizados (CustomEvent) o buses globales Flujo unidireccional y Elevación del Estado (Lifting State Up)
    Reutilización de Lógica Funciones auxiliares que manipulan el DOM Custom Hooks (useContador, useFormulario)
