    13.1: Fundamentos de TanStack Query

    1. Client State vs Server State

    En las aplicaciones web modernas existe una distinción crucial entre dos tipos de estado que requieren estrategias de arquitectura completamente distintas:

    • Client State (Estado de Cliente): Estado local, síncrono y efímero que pertenece exclusivamente a la interfaz de usuario. No se comparte con ninguna base de datos ni servidor remoto (ej. tema oscuro/claro, si un modal está abierto o cerrado, valores temporales de un formulario).
    • Server State (Estado de Servidor): Datos almacenados remotamente en un servidor o base de datos que la aplicación cliente solicita de forma asíncrona. No pertenece al cliente, es compartido con otros usuarios y puede quedar desactualizado (stale) en cualquier momento si no se sincroniza periódicamente.

    2. Configuración Inicial (QueryClient y QueryClientProvider)

    Para habilitar TanStack Query, es necesario instanciar la clase QueryClient y envolver el árbol de componentes principal con el proveedor <QueryClientProvider>.

    import React from 'react';
import ReactDOM from 'react-dom/client';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { App } from './App';

// Instancia global del cliente de consultas
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5, // Los datos se consideran "frescos" durante 5 minutos
      gcTime: 1000 * 60 * 10,    // La caché inactiva se elimina a los 10 minutos
      retry: 2,                  // Re-intenta 2 veces antes de lanzar error
      refetchOnWindowFocus: true, // Actualiza datos al volver a la pestaña
    },
  },
});

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <QueryClientProvider client="{queryClient}">
      <App/>
    </QueryClientProvider>
  </React.StrictMode>
);

    3. Claves de Consulta (Query Keys)

    Las Query Keys son arrays de elementos que identifican de forma única a cada consulta en la memoria caché. TanStack Query utiliza estas claves para la deduplicación, el almacenamiento en caché y la invalidación reactiva.

    Jerarquía de Claves

    Las claves deben organizarse desde lo general a lo específico:

    // 1. Clave de lista general
const keyTodos = ['todos'];

// 2. Clave de lista filtrada
const keyTodosFiltrados = ['todos', { estado: 'completado', pagina: 1 }];

// 3. Clave de elemento individual por ID
const keyTodoDetalle = ['todos', 42];

    Regla de Reactividad: Si un valor dinámico (ej. id, pagina, filtro) cambia dentro del array queryKey, TanStack Query ejecutará automáticamente una nueva petición para esa clave específica.

    4. El Hook useQuery: Ciclo de Vida y Estados

    El hook useQuery se utiliza para obtener y sincronizar datos de lectura (peticiones GET).

    import { useQuery } from '@tanstack/react-query';

interface Producto {
  id: number;
  nombre: string;
  precio: number;
}

async function fetchProducto(id: number): Promise<Producto> {
  const res = await fetch(`[https://api.ejemplo.com/productos/$](https://api.ejemplo.com/productos/$){id}`);
  if (!res.ok) throw new Error('Error al obtener el producto');
  return res.json();
}

export function DetalleProducto({ id }: { id: number }) {
  const { data, error, isLoading, isError, refetch } = useQuery({
    queryKey: ['productos', id],
    queryFn: () => fetchProducto(id),
    enabled: !!id, // Solo ejecuta si id existe
  });

  if (isLoading) return <p>Cargando producto...</p>;
  if (isError) return <p style={{ color: 'red' }}>Error: {(error as Error).message}</p>;

  return (
    <div>
      <h3>{data?.nombre}</h3>
      <p>Precio: ${data?.precio}</p>
      <button onClick={() => refetch()}>Recargar Datos</button>
    </div>
  );
}

    4.1. Conceptos Clave: staleTime vs gcTime

    Propiedad Definición Valor por Defecto
    staleTime Tiempo durante el cual los datos devueltos se consideran "frescos" (fresh). Mientras sean frescos, TanStack Query no volverá a solicitar datos al servidor. 0 (los datos caducan inmediatamente)
    gcTime (Garbage Collection Time) Tiempo que permanecen en memoria caché los datos de consultas inactivas (sin componentes suscritos) antes de ser eliminados del todo. 5 minutos (1000 * 60 * 5)

    4.2. Diagrama del Ciclo de Vida de la Caché

    stateDiagram-v2
    [*] --> Fresh: Petición Exitosa (Fresh)
    Fresh --> Stale: Transcurre staleTime
    Stale --> Fetching: Refetch (Window focus, reconnect, etc.)
    Fetching --> Fresh: Datos actualizados con éxito
    Stale --> Inactive: Componente se desmonta
    Inactive --> GarbageCollected: Transcurre gcTime sin suscriptores
    GarbageCollected --> [*]

    5. Estados de Consulta: status vs fetchStatus

    TanStack Query diferencia dos dimensiones independientes del estado:

    • status (Estado del Dato):
    • 'pending': Aún no hay datos en caché.
    • 'error': La petición falló.

    • 'success': Se tienen datos en caché listos para usar.

    • fetchStatus (Estado de la Petición HTTP):

    • 'fetching': Petición de red activa en segundo plano.
    • 'paused': La petición está en pausa por falta de conexión a Internet.
    • 'idle': La red no está realizando ninguna petición en este momento.

    6. Demostración Práctica Completa: Catálogo de Productos con Filtros y Caché

    Esta aplicación demuestra la obtención de datos con useQuery, filtrado reactivo mediante Query Keys dinámicas y retroalimentación de estado:

    import React, { useState } from 'react';
import { useQuery } from '@tanstack/react-query';

interface User {
  id: number;
  name: string;
  email: string;
  website: string;
}

// Función de consulta HTTP
async function fetchUsersBySearch(query: string): Promise<User[]> {
  const response = await fetch('[https://jsonplaceholder.typicode.com/users](https://jsonplaceholder.typicode.com/users)');
  if (!response.ok) {
    throw new Error('Error al conectar con la API de usuarios');
  }
  const users: User[] = await response.json();
  if (!query) return users;
  return users.filter((u) => u.name.toLowerCase().includes(query.toLowerCase()));
}

export function BuscadorUsuariosTanStack() {
  const [filtro, setFiltro] = useState<string>('');

  // Consulta administrada por TanStack Query
  const {
    data: usuarios = [],
    isLoading,
    isFetching,
    isError,
    error,
    refetch,
  } = useQuery({
    queryKey: ['usuarios', filtro], // Al cambiar 'filtro', reactiva la consulta
    queryFn: () => fetchUsersBySearch(filtro),
    staleTime: 1000 * 10, // 10 segundos de frescura
  });

  return (
    <div style={{ maxWidth: '600px', margin: '20px auto', fontFamily: 'sans-serif' }}>
      <h2>Directorio de Usuarios (TanStack Query)</h2>

      {/* Control de filtro local */}
      <input
        type="text"
        placeholder="Filtrar por nombre..."
        value={filtro}
        onChange={(e) => setFiltro(e.target.value)}
        style={{ width: '100%', padding: '8px', marginBottom: '10px' }}
      />

      <div style={{ marginBottom: '10px' }}>
        <button onClick={() => refetch()} disabled={isFetching}>
          {isFetching ? '🔄 Sincronizando...' : 'Re-sincronizar Ahora'}
        </button>
        {isFetching && !isLoading && (
          <span style={{ marginLeft: '10px', color: '#0288d1', fontSize: '13px' }}>
            [Actualizando en segundo plano...]
          </span>
        )}
      </div>

      {/* Manejo de estados de interfaz */}
      {isLoading && <p>⌛ Carga inicial de datos...</p>}
      {isError && <p style={{ color: 'red' }}>❌ Error: {(error as Error).message}</p>}

      {!isLoading && !isError && (
        <ul style={{ listStyle: 'none', padding: 0 }}>
          {usuarios.map((user) => (
            <li
              key={user.id}
              style={{
                border: '1px solid #ccc',
                padding: '10px',
                marginBottom: '5px',
                borderRadius: '4px',
              }}
            >
              <strong>{user.name}</strong> - {user.email}
              <br />
              <small>🌐 {user.website}</small>
            </li>
          ))}
          {usuarios.length === 0 && <li>No se encontraron resultados.</li>}
        </ul>
      )}
    </div>
  );
}
