    7.1. React: Arquitectura Interna, Virtual DOM, Fiber Reconciler, Hooks y Ciclo de Vida

    7.1.1. Origen, Filosofía y Principios Arquitectónicos

    React no fue concebido como un framework MVC/MVVM tradicional de tipo "baterías incluidas" (como Angular), sino como una librería orientada exclusivamente a la capa de vista (View) mediante un enfoque funcional e inmutable.

    • Origen: Fue creado por Jordan Walke en Facebook (2011/2013) tras experimentos previos como FaxJS, para resolver los cuellos de botella de sincronización de estado en el News Feed de Facebook e Instagram.

    • Inmutabilidad como Motor de Cambio: En lugar de observar y mutar propiedades individuales de objetos JavaScript en tiempo de ejecución, React exige tratar el estado como estructuras de datos inmutables. Para actualizar la vista, se reemplaza la referencia del estado anterior por una nueva copia modificada.

    • La Ecuación Fundamental:

    $$\text{UI} = f(\text{State})$$

    La interfaz de usuario es una proyección directa y declarativa del estado de la aplicación en un instante determinado.

    7.1.2. El Lenguaje del Componente: JSX y el Proceso de Transpilación

    JSX (JavaScript XML) es una extensión sintáctica de ECMAScript que permite escribir marcado estructurado de tipo HTML directamente dentro del código JavaScript.

    JSX no es HTML ni se inserta directamente como una cadena de texto en el DOM. Compiladores como Babel, SWC o ESBuild transforman la sintaxis JSX en llamadas a funciones de JavaScript que instancian objetos en memoria.

    // 1. Código escrito en JSX
const elemento = (
  <button className="btn-primary" onClick={handleClick}>
    <span>Enviar</span>
  </button>
);

// 2. Resultado de la transpilación (React.createElement / Transformador JSX)
const elementoTranspilado = React.createElement(
  'button',
  { className: 'btn-primary', onClick: handleClick },
  React.createElement('span', null, 'Enviar')
);

    La ejecución de React.createElement() produce un React Element: un objeto JavaScript plano (Plain Old JavaScript Object - POJO) que describe un nodo de la interfaz de usuario en el Virtual DOM:

    // Objeto JS resultante en memoria RAM (Nodo del Virtual DOM)
{
  $$typeof: Symbol(react.element),
  type: 'button',
  props: {
    className: 'btn-primary',
    onClick: handleClick,
    children: {
      type: 'span',
      props: { children: 'Enviar' }
    }
  },
  key: null,
  ref: null
}

    7.1.3. Arquitectura Interna: Virtual DOM y el Motor React Fiber

    El Virtual DOM y la Complejidad del Diffing

    El Virtual DOM (VDOM) es una representación ligera del DOM Real mantenida en memoria RAM. Cuando el estado de la aplicación cambia, React genera un nuevo árbol VDOM y ejecuta el proceso de Reconciliación (Reconciliation) comparándolo con el árbol anterior.

    Un algoritmo genérico para comparar dos árboles y calcular la cantidad mínima de operaciones tiene una complejidad temporal de $O(n^3)$, donde $n$ es el número de nodos. Para un árbol de 1,000 elementos, esto requeriría aproximadamente $10^9$ operaciones, colapsando el hilo principal del navegador.

    React reduce esta complejidad a un orden lineal $O(n)$ mediante dos reglas heurísticas:

    1. Tipos de Elementos Distintos: Dos elementos de diferente tipo (por ejemplo, cambiar un <div> por un <section>) generarán árboles completamente diferentes. React destruye el subárbol anterior por completo (desmontando sus componentes) y construye el nuevo subárbol desde cero.

    2. Propiedad key en Listas Dinámicas: Al renderizar colecciones de elementos, la propiedad key proporciona un identificador único y estable. Permite a React detectar reordenamientos, inserciones o eliminaciones sin necesidad de recrear los nodos del DOM Real.

    React Fiber (El Motor de Reconciliación)

    Introducido a partir de React 16, Fiber es una reescritura completa del algoritmo de reconciliación. Su objetivo principal es permitir la renderización concurrente (Concurrent Rendering).

    Un Fiber representa una unidad de trabajo estructurada como un nodo de una lista doblemente enlazada. Su arquitectura divide el proceso de renderizado en dos fases bien diferenciadas:

    7.1.4. Flujo Unidireccional de Datos y Comunicación entre Componentes

    El flujo de información en React es estrictamente descendente (top-down).

    • Props (Propiedades): Parámetros de entrada inmutables pasados de componentes padres a componentes hijos. Un componente hijo nunca debe mutar sus propias props.

    • State (Estado): Información mutable gestionada internamente por un componente que se preserva entre re-renderizados.

    flowchart TD
    Parent["<b>Componente Padre</b><br>Mantiene el Estado: 'usuario'"] -- "1. Pasa datos vía Props" --> Child["<b>Componente Hijo (Formulario)</b>"]
    Child -- "2. Invoca Callback (onSave)" --> Parent
    Parent -- "3. setState() actualiza el Estado" --> Parent
    Parent -- "4. Re-renderizado con nuevo Estado" --> Child

    Canales de Comunicación:

    1. Padre a Hijo: Paso directo de datos a través de props.

    2. Hijo a Padre: El padre pasa una función callback como prop; el hijo invoca dicha función pasando los nuevos datos como argumento.

    3. Componentes Distantes: Para evitar el arrastre manual de datos a través de componentes intermedios (Prop Drilling), se utiliza la Context API o gestores de estado centralizados (Zustand, Redux Toolkit).

    7.1.5. El Modelo Reactivo Funcional: Hooks y Ciclo de Vida

    Con la llegada de React 16.8 (2019), los Hooks sustituyeron la definición de componentes basada en clases ES6 por funciones puras con celdas de estado vinculadas a la fibra del componente.

    Hooks Fundamentales y Ciclo de Vida:

    • useState: Declara una variable de estado y su función actualizadora. 

      const [contador, setContador] = useState<number>(0);

    • useEffect: Unifica el comportamiento de componentDidMount, componentDidUpdate y componentWillUnmount para gestionar efectos secundarios (peticiones API, suscripciones o eventos del DOM).

    useEffect(() => {
  // Código ejecutado tras el renderizado (Mount / Update)
  const suscripcion = canal.conectar();

  // Función de limpieza (Cleanup Function - Unmount)
  return () => {
    suscripcion.desconectar();
  };
}, [dependencia]); // Se re-ejecuta si el valor de 'dependencia' cambia
    • useMemo y useCallback:
    • useMemo: Memoriza el resultado de un cálculo intensivo para no reevaluarlo salvo que sus dependencias varíen.

    • useCallback: Memoriza la referencia en memoria de una función para evitar el re-renderizado de componentes hijos optimizados con React.memo.

    • useRef: Devuelve un objeto mutable { current: valor } que persiste durante todo el ciclo de vida del componente sin desencadenar re-renderizados al ser modificado. Se usa para referencias directas al DOM Real (HTMLInputElement, HTMLCanvasElement).

    7.1.6. Ejemplo Práctico Integrador (TypeScript + JSX)

    El siguiente ejemplo implementa una interfaz declarativa con gestión de estado inmutable, efectos secundarios asíncronos y referencias al DOM:

    import React, { useState, useEffect, useRef } from 'react';

// Interfaz que define el contrato de datos
interface Usuario {
  id: number;
  nombre: string;
  email: string;
}

export const GestorUsuarios: React.FC = () => {
  // 1. Estado inmutable para usuarios y control de carga
  const [usuarios, setUsuarios] = useState<Usuario[]>([]);
  const [cargando, setCargando] = useState<boolean>(true);

  // 2. Referencia directa al nodo del DOM para lectura imperativa puntual
  const inputNombreRef = useRef<HTMLInputElement>(null);

  // 3. Efecto secundario: Carga de datos al montar el componente (Mount)
  useEffect(() => {
    let activo = true;

    const obtenerUsuarios = async () => {
      try {
        const respuesta = await fetch('https://jsonplaceholder.typicode.com/users');
        const datos: Usuario[] = await respuesta.json();

        if (activo) {
          setUsuarios(datos);
          setCargando(false);
        }
      } catch (error) {
        console.error('Error al recuperar usuarios:', error);
        if (activo) setCargando(false);
      }
    };

    obtenerUsuarios();

    // Cleanup: evita actualizar el estado si el componente se desmonta mientras carga
    return () => {
      activo = false;
    };
  }, []); // Array de dependencias vacío = Se ejecuta únicamente una vez al montar

  // 4. Manejador de eventos con actualización inmutable de estado
  const agregarUsuario = (evento: React.FormEvent) => {
    evento.preventDefault();
    const nombreIngresado = inputNombreRef.current?.value.trim();

    if (!nombreIngresado) return;

    const nuevoUsuario: Usuario = {
      id: Date.now(),
      nombre: nombreIngresado,
      email: `${nombreIngresado.toLowerCase().replace(/\s+/g, '')}@ejemplo.com`
    };

    // Inmutabilidad: Se crea una nueva referencia de array mediante Spread Operator
    setUsuarios((prevUsuarios) => [...prevUsuarios, nuevoUsuario]);

    // Limpieza directa del input a través de la ref
    if (inputNombreRef.current) {
      inputNombreRef.current.value = '';
    }
  };

  if (cargando) {
    return <p className="mensaje-estado">Cargando directorio de usuarios...</p>;
  }

  return (
    <section className="contenedor-gestion">
      <h2>Catálogo de Usuarios ({usuarios.length})</h2>

      <form onSubmit={agregarUsuario} className="formulario-nuevo">
        <input
          ref={inputNombreRef}
          type="text"
          placeholder="Nombre del nuevo usuario"
          className="input-texto"
        />
        <button type="submit" className="btn-guardar">
          Añadir Usuario
        </button>
      </form>

      <ul className="lista-tarjetas">
        {usuarios.map((usuario) => (
          <li key={usuario.id} className="tarjeta-item">
            <strong>{usuario.nombre}</strong>
            <span>{usuario.email}</span>
          </li>
        ))}
      </ul>
    </section>
  );
};
