    UD 6: Asincronía y Almacenamiento (Storage/Vite) (RA3)

    Referencia Módulo DWEC: Resultado de Aprendizaje 3 (RA3) — Gestiona la programación asíncrona en el entorno cliente (Promesas, async/await, Fetch API) y el almacenamiento persistente de datos en el navegador (Web Storage), integrando herramientas de construcción modernas como Vite.

    Esta unidad continúa directamente sobre los fundamentos de manipulación del DOM y gestión de eventos estudiados en la UD 5.

    1. Asincronía en JavaScript y el Event Loop 🔄

    JavaScript es un lenguaje de un solo hilo (single-threaded), lo que significa que solo puede ejecutar una tarea a la vez en su hilo principal de ejecución. Para gestionar operaciones lentas (peticiones de red, temporizadores) sin congelar la interfaz, utiliza un modelo de concurrencia basado en el Event Loop.

    Arquitectura del Event Loop

    flowchart LR
    CallStack["Call Stack (Pila de Ejecución)"] -->|Ejecuta código síncrono| WebAPIs["Web APIs (setTimeout, fetch, DOM)"]
    WebAPIs -->|Operación completada| TaskQueues

    subgraph TaskQueues ["Colas de Tareas"]
        MicroTasks["Microtask Queue (Promises, queueMicrotask) - ALTA PRIORIDAD"]

    End

    TaskQueues -->|Event Loop comprueba si Call Stack está vacío| EventLoop{"Event Loop"}
    EventLoop -->|Empuja tareas a| CallStack
    1. Call Stack (Pila de Ejecución): Registra las funciones que se están ejecutando.
    2. Web APIs: Hilos del navegador que gestionan peticiones fetch, temporizadores y eventos.
    3. Microtask Queue: Cola de alta prioridad para llamadas de Promesas (.then, await).
    4. Macrotask Queue (Callback Queue): Cola para setTimeout, setInterval y eventos del DOM.

    Regla de Prioridad: El Event Loop siempre vacía por completo la Microtask Queue antes de tomar una tarea de la Macrotask Queue.

    Promesas (Promises)

    Una Promesa es un objeto que representa el resultado eventual de una operación asíncrona. Puede estar en uno de tres estados:

    • pending: Estado inicial, operación en proceso.
    • fulfilled: Operación completada con éxito (resolve).
    • rejected: Operación fallida (reject).
    // Creación de una promesa
function solicitarDatos(exito) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (exito) {
        resolve({ status: 200, data: "Datos recibidos correctamente" });
      } else {
        reject(new Error("Error 500: Fallo en la conexión con el servidor"));
      }
    }, 1500);
  });
}

// Consumo con .then(), .catch() y .finally()
solicitarDatos(true)
  .then((respuesta) => {
    console.log(respuesta.data);
    return "Procesando datos...";
  })
  .then((paso2) => console.log(paso2))
  .catch((error) => console.error(error.message))
  .finally(() => console.log("Operación asíncrona finalizada."));

    Métodos Estáticos de Promesas

    const p1 = fetch("/api/usuarios");
const p2 = fetch("/api/productos");

// Promise.all(): Espera a que TODAS se cumplan. Si UNA falla, rechaza inmediatamente.
Promise.all([p1, p2])
  .then(([resUsuarios, resProductos]) => console.log("Ambas peticiones completadas"))
  .catch((err) => console.error("Al menos una petición falló", err));

// Promise.allSettled(): Espera a que TODAS terminen (sin importar si se cumplen o rechazan).
Promise.allSettled([p1, p2]).then((resultados) => {
  resultados.forEach((res) => console.log(res.status)); // "fulfilled" o "rejected"
});

// Promise.race(): Retorna la PRIMERA promesa en finalizar (cumplida o rechazada).

    Sintaxis async / await

    Introducida en ES2017, es azúcar sintáctica sobre Promesas que permite escribir código asíncrono con una estructura visualmente síncrona.

    • La palabra clave async antepuesta a una función hace que esta devuelva siempre una Promesa.
    • La palabra clave await solo puede usarse dentro de funciones async y pausa la ejecución hasta que la Promesa se resuelve.
    async function obtenerDatosProcesados() {
  try {
    console.log("Iniciando petición...");
    // La ejecución se detiene de forma no bloqueante hasta resolver la promesa
    const respuesta = await solicitarDatos(true); 
    console.log("Respuesta recibida:", respuesta.data);
    return respuesta.data;
  } catch (error) {
    // Control de errores unificado mediante try...catch
    console.error("Capturado en el catch:", error.message);
  } finally {
    console.log("Limpieza de recursos finalizada.");
  }
}

    2. Peticiones HTTP Asíncronas con Fetch API 🌐

    La Fetch API proporciona una interfaz para realizar peticiones HTTP asíncronas (GET, POST, PUT, DELETE) a servidores remotos mediante el uso de Promesas.

    Estructura Básica de una Petición GET

    async function cargarUsuarios() {
  try {
    const respuesta = await fetch("https://jsonplaceholder.typicode.com/users");

    // IMPORTANTE: fetch NO rechaza la promesa ante errores HTTP (404, 500). 
    // Se debe comprobar manualmente la propiedad response.ok
    if (!respuesta.ok) {
      throw new Error(`Error HTTP Status: ${respuesta.status}`);
    }

    // Parsea la respuesta codificada en JSON a un Objeto/Array JavaScript
    const usuarios = await respuesta.json();
    console.log("Usuarios cargados:", usuarios);
  } catch (error) {
    console.error("Fallo de red o servidor:", error);
  }
}

    Envío de Datos mediante Peticiones POST / PUT / DELETE

    async function crearNuevoProducto(producto) {
  const URL = "https://api.ejemplo.com/v1/productos";

  try {
    const respuesta = await fetch(URL, {
      method: "POST", // Método HTTP
      headers: {
        "Content-Type": "application/json", // Especifica el formato del cuerpo
        "Authorization": "Bearer TOKEN_JWT_AQUÍ"
      },
      body: JSON.stringify(producto) // Convierte el objeto JS a cadena JSON
    });

    if (!respuesta.ok) {
      throw new Error(`Error al crear producto. Código: ${respuesta.status}`);
    }

    const productoCreado = await respuesta.json();
    return productoCreado;
  } catch (error) {
    console.error("Error en la operación POST:", error);
  }
}

// Invocación
crearNuevoProducto({ nombre: "Monitor 4K", precio: 350 });

    3. Almacenamiento en el Cliente (Web Storage API) 💾

    La Web Storage API permite guardar pares clave-valor dentro del navegador web de manera sencilla.

    Manipulación e Integración con Serialización JSON

    Los métodos de Web Storage solo pueden almacenar cadenas de texto (String). Para guardar Objetos o Arrays se requiere serializar con JSON.stringify() y deserializar con JSON.parse().

    // Objeto de estado a persistir
const configuracionUsuario = {
  tema: "oscuro",
  idioma: "es",
  notificaciones: true
};

// 1. GUARDAR (setItem): Objeto -> Cadena JSON
localStorage.setItem("user_config", JSON.stringify(configuracionUsuario));

// 2. RECUPERAR (getItem): Cadena JSON -> Objeto JS
const configGuardadaString = localStorage.getItem("user_config");

if (configGuardadaString) {
  const configObj = JSON.parse(configGuardadaString);
  console.log(`Tema activo: ${configObj.tema}`); // "oscuro"
}

// 3. ELIMINAR UN ELEMENTO (removeItem)
localStorage.removeItem("user_config");

// 4. LIMPIAR TODO EL ALMACENAMIENTO (clear)
localStorage.clear();

    4. Caso Práctico Integrado — Repaso de UD5 y UD6 (DOM + Eventos + Async + Fetch + Storage) 🛠️

    A continuación se presenta un módulo completo que integra todos los bloques conceptuales abordados en la unidad:

    // Modulo de Gestión de Tareas Asíncronas
document.addEventListener("DOMContentLoaded", () => {
  const formulario = document.querySelector("#form-tarea");
  const inputTitulo = document.querySelector("#input-titulo");
  const contenedorLista = document.querySelector("#lista-tareas");

  // Carga inicial del almacenamiento local o de la API si está vacío
  inicializarApp();

  formulario.addEventListener("submit", async (e) => {
    e.preventDefault();
    const titulo = inputTitulo.value.trim();
    if (!titulo) return;

    const nuevaTarea = { id: Date.now(), titulo, completada: false };

    // Renderizado en DOM e inserción en Storage
    renderizarTarea(nuevaTarea);
    guardarEnStorage(nuevaTarea);

    inputTitulo.value = "";
  });

  // Delegación de eventos para marcar como completada
  contenedorLista.addEventListener("click", (e) => {
    if (e.target.matches(".btn-completar")) {
      const li = e.target.closest("li");
      li.classList.toggle("completada");
    }
  });

  async function inicializarApp() {
    const tareasLocales = JSON.parse(localStorage.getItem("tareas")) || [];

    if (tareasLocales.length > 0) {
      tareasLocales.forEach(renderizarTarea);
    } else {
      // Si no hay datos locales, obtiene tareas iniciales desde un servidor
      try {
        const res = await fetch("https://jsonplaceholder.typicode.com/todos?_limit=3");
        const datos = await res.json();
        datos.forEach((t) => {
          const tarea = { id: t.id, titulo: t.title, completada: t.completed };
          renderizarTarea(tarea);
          guardarEnStorage(tarea);
        });
      } catch (err) {
        console.error("Error al cargar datos iniciales:", err);
      }
    }
  }

  function renderizarTarea(tarea) {
    const html = `
      <li data-id="${tarea.id}" class="${tarea.completada ? 'completada' : ''}">
        <span>${tarea.titulo}</span>
        <button class="btn-completar">Cambiar Estado</button>
      </li>
    `;
    contenedorLista.insertAdjacentHTML("beforeend", html);
  }

  function guardarEnStorage(tarea) {
    const tareas = JSON.parse(localStorage.getItem("tareas")) || [];
    tareas.push(tarea);
    localStorage.setItem("tareas", JSON.stringify(tareas));
  }
});
