    UD 9: Formularios y Validaciones (RA5) — Visión General y Mapa Curricular

    1. Presentación y Contextualización Curricular

    La Unidad Didáctica 9 representa la culminación de la construcción de interfaces interactivas en el cliente. Si en las unidades previas se asentaron las bases del manejo de eventos (SyntheticEvent) y la mutación de la memoria del componente mediante el estado local (useState), esta unidad se centra en el escenario más complejo y crítico en aplicaciones web empresariales: la captura, procesamiento, validación y envío de datos estructurados introducidos por el usuario mediante formularios.

    Los formularios representan la puerta de entrada principal para la interacción bi-direccional entre el cliente y el servidor. Un diseño deficiente de la gestión de formularios no solo degrada la Experiencia de Usuario (UX), sino que afecta negativamente al rendimiento de la aplicación (debido a re-renderizados innecesarios) y compromete la seguridad e integridad de los datos que se envían al backend.

    En esta unidad, el alumnado evolucionará desde la gestión nativa imperativa e intermedia de formularios en React hacia las prácticas y herramientas utilizadas en la industria del software:

    1. Mecanismos de Control de Entradas y Estilado Moderno: Contraste profundo entre Componentes Controlados (sincronización con useState) y Componentes No Controlados (persistencia en el DOM mediante useRef/FormData) maquetados con Tailwind CSS.
    2. Optimizaciones de Rendimiento y Gestión de Estado: Adopción de la librería React Hook Form, que utiliza entradas no controladas con suscripciones aisladas para garantizar un rendimiento de renderizado $O(1)$ por pulsación de tecla.
    3. Validación Declarativa y Tipado Estricto: Construcción de esquemas de validación mediante Zod, permitiendo derivar tipos de TypeScript automáticamente y desacoplar la lógica de validación de la capa de presentación JSX.

    2. Resultado de Aprendizaje y Criterios de Evaluación (RA5)

    Esta unidad didáctica profundiza y completa la adquisición de competencias asociadas al Resultado de Aprendizaje 5 (RA5) del módulo profesional de Desarrollo Web en Entorno Cliente (DWEC):

    RA5: Desarrolla aplicaciones web dinámicas integrando la gestión de eventos de usuario, la persistencia y actualización del estado local, y la reutilización de lógica mediante componentes y hooks personalizados.

    Desglose Detallado de Criterios de Evaluación (CE):

    • CE5.a: Se han comparado las arquitecturas de componentes controlados y no controlados para la captura de entradas de usuario, evaluando su impacto en el rendimiento y la complejidad del código.
    • CE5.b: Se han implementado controles de formulario complejos (input, select, textarea, checkbox, radio group, file) garantizando la correcta vinculación de sus datos.
    • CE5.c: Se ha integrado la librería React Hook Form mediante el hook useForm para gestionar el ciclo de vida, el registro de campos y la recolección de datos de manera optimizada.
    • CE5.d: Se han definido esquemas de validación declarativos con Zod, aplicando restricciones de longitud, patrones regex, campos opcionales, transformaciones de tipo y validaciones cruzadas entre campos.
    • CE5.e: Se ha automatizado la inferencia de tipos en TypeScript a partir de esquemas Zod utilizando z.infer, garantizando la sincronización entre la validación en tiempo de ejecución y el sistema de tipos en tiempo de compilación.
    • CE5.f: Se ha gestionado el estado de interacción del formulario (isDirty, isTouched, isValid, isSubmitting, errors) para proporcionar retroalimentación visual en tiempo real y mejorar la experiencia de usuario.
    • CE5.g: Se han incorporado atributos de accesibilidad nativos y de WAI-ARIA (aria-invalid, aria-describedby, htmlFor) vinculando de forma unívoca las etiquetas, campos de texto y mensajes de error.

    4. Mapa Conceptual y Arquitectura del Flujo de Datos

    El siguiente diagrama de secuencia detalla el ciclo completo de vida de un formulario profesional en React:

    sequenceDiagram
    autonumber
    actor User as Usuario (Navegador)
    participant Input as Input DOM (No Controlado)
    participant RHF as React Hook Form (useForm)
    participant Zod as Resolver Zod (registroSchema)
    participant Component as Componente React (UI)
    participant Handler as onSubmit Handler (API / Server)

    User->>Input: Escribe caracteres / Cambia selección / Pierde foco (blur)
    Input->>RHF: Dispara evento registrado sin re-renderizar todo el formulario

    opt Modo de validación activo (ej. onBlur / onTouched)
        RHF->>Zod: Envía datos actuales para validación de esquema
        alt Fallo de Validación
            Zod-->>RHF: Devuelve árbol de errores (ZodError)
            RHF->>Component: Re-renderiza ÚNICAMENTE el mensaje de error del campo afectado
            Component-->>User: Muestra error específico y actualiza aria-invalid="true"
        else Validación Exitosa
            Zod-->>RHF: Confirmación de datos válidos
            RHF->>Component: Limpia estado de error del campo
        end
    end

    User->>Input: Clic en botón "Enviar" (<button type="submit">)
    Input->>RHF: Intercepta e.preventDefault() vía handleSubmit
    RHF->>Zod: Ejecuta validación completa de todos los campos del esquema

    alt Esquema Inválido
        Zod-->>RHF: Objeto de errores global
        RHF->>Component: Marca campos como isTouched, muestra errores y enfoca el 1er campo erróneo
    else Esquema Válido
        Zod-->>RHF: Objeto de datos parseado y fuertemente tipado
        RHF->>Handler: Invoca a onSubmitHandler(data) estableciendo isSubmitting = true
        Handler->>Handler: Envío asíncrono (fetch / axios) a la API REST
        Handler-->>RHF: Promesa resuelta
        RHF->>Component: Restablece estado isSubmitting = false y ejecuta reset()
    end

    5. Cuadro Comparativo Integrado de Enfoques de Formulario

    Dimensión Formulario HTML5 / JS Vanilla Componente Controlado (useState) Componente No Controlado (useRef / FormData) React Hook Form + Zod Schema
    Almacenamiento del Estado Nodos del DOM Nativo Estado local de React (useState) Nodos del DOM accesibles vía useRef Referencias internas gestionadas por la librería
    Rendimiento de Escritura $O(1)$ (Nativo) Bajo: $O(N)$ re-renders por cada tecla tecleada $O(1)$ (Sin re-renders durante la escritura) Óptimo: $O(1)$ re-renders (aislado por celda suscrita)
    Complejidad del Código Baja pero imperativa Media / Alta (Múltiples onChange y estados) Media (Extracción manual con FormData) Baja y Declarativa
    Validación Atributos HTML5 nativos (required) Manual con condicionales if-else en JS Manual tras el evento submit Declarativa basada en esquemas (Zod)
    Tipado TypeScript Ninguno / Manual (any) Manual (interface creada a mano) Manual extrayendo del DOM Inferencia automática (z.infer<typeof schema>)
    Accesibilidad (a11y) Básica nativa Manual (Sincronización manual de atributos) Manual Automatizada mediante props WAI-ARIA
